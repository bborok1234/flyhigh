# 두 번째 프로젝트 데이터 파이프라인 확장

## 왜 필요한가

두 번째 repo가 생성되었으므로 다음 품질 증거는 로컬 예제 입력을 넘어 adapter, registry, report artifact로 확장하는 것이다.

## 목적

두 번째 프로젝트가 Flyhigh 위에서 지속 가능한 작업 단위로 확장될 수 있게 데이터 입력, registry, report artifact의 경계를 세운다.

## 수용 기준

- adapter 인터페이스가 정의된다.
- registry가 작업 단위를 분리한다.
- report artifact schema가 검증된다.
- Flyhigh run artifact와 dashboard에 결과가 기록된다.
